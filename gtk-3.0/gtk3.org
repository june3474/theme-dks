*** selection
selection is not a widget but a css subnode when a widget--such as GtkText(text) and
GtkLabel(label)--has a selection.
Below are the css nodes of text widget.

text[.read-only]
├── placeholder
├── undershoot.left
├── undershoot.right
├── [selection]
├── [block-cursor]
╰── [window.popup]
[[https://docs.gtk.org/gtk4/class.Text.html][link]]

** button
GtkButton has a single CSS node with name button. The node will get the style classes .image-button or .text-button, if the content is just an image or label, respectively. It may also receive the .flat style class.

Button-like widgets like GtkToggleButton, GtkMenuButton, GtkVolumeButton, GtkLockButton, GtkColorButton or GtkFontButton use style classes such as .toggle, .popup, .scale, .lock, .color on the button node to differentiate themselves from a plain GtkButton.
[[https://docs.gtk.org/gtk3/class.Button.html][link]]

*** window
GtkWindow has a main CSS node with name window and style class .background, and a subnode with name decoration.
Style classes that are typically used with the main CSS node are .csd (when client-side decorations are in use), .solid-csd (for client-side decorations without invisible borders), .ssd (used by mutter when rendering server-side decorations). GtkWindow also represents window states with the following style classes on the main node: .tiled, .maximized, .fullscreen. Specialized types of window often add their own discriminating style classes, such as .popup or .tooltip.
GtkWindow adds the .titlebar and .default-decoration style classes to the widget that is added as a titlebar child.

window.background
├── decoration
├── <titlebar child>.titlebar [.default-decoration]
╰── <child>
[[https://docs.gtk.org/gtk4/class.Window.html][link]]

#+begin_src css

  /*************************************************/
  /*                 WINDOW                        */
  /*************************************************/

  window {
      color: @fg_color;
      background-color: @bg_color;
      /* decoration node가 없을 경우 fallback */
      border: 1px solid @window_border_color;
      /* 아래에 적은 것처럼 xfce에서는 무시될 가능성이 높지만 해가 될 건 없음.
         다른 wm을 사용할 경우도 있으니...
         Anyhow, shadow는 theme 설정과 무관하게 compositor로 그려질 수 있다. */
      box-shadow: 0px 0px 4px 2px rgba(0,0,0,0.4);
  }

  window:backdrop {
      border-color: @window_unfocused_border_color;
      /* if set box-shadow to none, window changes it position
         and size by the size of box-shadow. So just make it transparent
         by setting the alpah to zero */
      box-shadow: 0px 0px 4px 2px rgba(0,0,0,0);
  }

  /*
     모든 GtkWindow는 만들어질 때 decoration이라는 CSS 자식 노드를 하나 가짐.
     그러나 decoration 노드에 적용되는 css는 최대화나 전체 화면이 아닌 .csd 창에서만
     작동함.
     decoration 노드가 있는 경우 window 노드의 property를 오버라이드함.
     다만, window > decoration은 윈도우의 일부(타이틀바나 외곽선)에만 적용됨.
     전체 윈도우에 색을 입히고 싶으면 window 스타일이 적용됨.

     참고로, gtk4는 decoration node가 없고 .csd, .ssd 등이 style class로 사용됨.
     window 노드 자체가 .csd class를 달고 틀과 그림자를 그림. 그래서 둥근 모서리를
     GTK4는 window에, GTK3는 window > decoration에 줘야 함.
     ,*NOTICE*: 컴포지터 여부에 따라 창에 붙는 class가 달라짐.
     window.csd: 컴포지터가 켜져 있고 투명 창을 쓸 수 있을 때. 그림자와 투명한
                 모서리가 가능함. 지금 환경(use_compositing=true)이 여기에 해당.
     window.solid-csd: 컴포지터가 꺼져 있을 때. 투명한 영역이 없으므로 둥근 모서리
                       바깥이 투명하지 않고 칠해져 보임.

     ## gtk3 .csd 창에서 decoration의 CSS 속성과 역할 ##
     border, background-color: 창의 바깥 테두리와 바탕
     border-radius: 바깥 틀의 둥근 모서리
     box-shadow: 창 그림자
     margin: 그림자와 크기 조절 손잡이가 들어갈 투명 여백
     margin과 box-shadow 크기는 창 바깥의 보이지 않는 여백으로 계산되고, GTK는 이
     크기를 창 관리자에 알려서(_GTK_FRAME_EXTENTS) 창 관리자가 그 여백을 창 밖으로
     취급하게 함.

     ## gtk3 window 하나는 세 겹으로 그려짐 ##
     CSS 노드로는 decoration, headerbar, 내용이 모두 window의 자식임.
     실제로는 아래 순서로 겹쳐 그려짐.  ￼
     ① decoration: 바깥 틀 (테두리·그림자·둥근 모서리)   ← CSD일 때만
     ② window 노드: 제목줄 아래 내용 영역의 배경·테두리
     ③ headerbar.titlebar : 자기 배경과 자기 border-radius
     패널처럼 장식 없는 창은 제목줄도 틀도 없어서, ②가 곧 창 전체이므로 window에
     radius를 주면 패널 모서리가 잘림.

     XFCE의 Xfwm4는 기본적으로 server-side-decoration(ssd)을 사용하기 때문에
     decoration 노드가 csd가 활성화 되어 있을 때 나타남.
     XFCE(Xfwm4)는 csd를 부분적으로 지원하며, 많은 경우 제대로 된 그림자, 그림테두리,
     리사이즈 핸들 등은 제대로 작동하지 않을 수 있음.

     ✅ 적용되지 않거나 제한적인 CSS 속성들 -- from ChatGPT
     속성      설명        window / decoration에서의 동작
     padding   내부 여백   무시되거나 시각적으로 영향 없음 (내용에만 영향)
     margin    외부 여백       무시됨. 윈도우는 "부모"가 없기 때문에 쓸모 없음
     box-shadow    그림자      많은 경우 무시됨, 특히 Xfwm4/X11 환경
     border-radius 테두리     CSD 환경에서는 부분적으로 작동, X11에서는 거의 무시됨
     opacity   투명도      GTK 자체는 지원하지만, WM이 지원 안 하면 무시됨
     transform 회전,스케일    적용되지 않음. layout 레벨에서만 작동
     background-image      일부 환경에서는 동작 안 함, 특히 decoration 노드
     min-width/min-height  최소 크기   window 노드에는 무시됨
     display   none 등     GTK CSS는 display 속성을 아예 지원하지 않음

     ✅ 반대로 적용 잘 되는 속성들

  ,*/
